# 模型价格编辑面板 Header 操作区设计

## 背景

当前模型价格编辑器把 `取消` 和 `更新` / `添加` 操作放在
`ModelPricingEditorPanel` 的底部 Footer 中。桌面端中，这个编辑器是价格表右侧的
sticky 编辑面板；移动端中，同一个编辑器显示在 Sheet 抽屉里。

当价格表单较长时，尤其是表达式计费编辑器或保存预览展开后，底部 Footer 不方便触达。
管理员需要滚动到面板底部，才能把单个模型的编辑内容应用到设置草稿中。

## 目标

将模型价格编辑器的操作按钮移动到面板 Header，使用户打开编辑器后立即能看到并操作。

此变更不能改变现有的两段式保存流程：

1. `更新` / `添加` 只把单个模型的编辑内容写入前端设置草稿。
2. `保存模型价格` 才会通过后端接口持久化更新后的价格 JSON 配置。

## 范围

本次包含：

- 将 `取消` 和 `更新` / `添加` 从编辑器底部 Footer 移到 Header。
- 删除编辑器底部操作区。
- 保持现有提交和取消行为不变。
- 删除 Footer 后，仍保留“当前操作只写入设置草稿”的提示信息。
- 确保 Header 布局在桌面端和窄屏移动端 Sheet 中都可用。

本次不包含：

- 修改模型价格数据写入草稿的逻辑。
- 修改最终 `保存模型价格` 的持久化流程。
- 添加自动保存。
- 重构价格配置存储或计费逻辑。

## 选定布局

采用左侧内容、右侧操作的 Header 布局。

左侧：

- 编辑器标题：`编辑模型价格` 或 `添加模型价格`。
- 当前模型名，必要时截断。
- 现有价格模式 Badge。

右侧：

- `取消` outline 按钮。
- `更新` / `添加` primary 按钮。

窄屏场景下，Header 应允许换行：标题和元信息保留在第一块区域，操作按钮移动到下方
或独立成一行，避免长模型名和按钮互相挤压或重叠。

## 行为

移动后的按钮保持当前行为：

- `取消` 调用现有 `onCancel` 回调。
- `更新` / `添加` 提交现有表单，并调用现有 `handleSubmit`。
- 表单校验行为不变。
- 提交按钮文案继续由编辑模式决定：
  - 编辑已有模型：`更新`
  - 新增模型：`添加`

当前 Footer 中的草稿提示在删除 Footer 后仍需保留。该提示应放在编辑器顶部附近，
例如 Header 下方或保存预览附近，让用户明确知道单模型操作只更新草稿，真正入库仍需点击
页面级的 `保存模型价格`。

## 组件

主要组件：

- `web/src/features/system-settings/models/model-pricing-sheet.tsx`
  - `ModelPricingEditorPanel`

相关调用方不应需要行为变更：

- `ModelPricingSheet`
- `ModelRatioVisualEditor`

## 数据流

预期不改变数据流。

现有流程保持如下：

1. 用户编辑模型价格字段。
2. Header 中的 `更新` / `添加` 提交编辑器表单。
3. `ModelPricingEditorPanel.handleSubmit` 构造 `ModelRatioData`。
4. 父组件 `ModelRatioVisualEditor.handleSave` 将该模型配置写入价格 JSON 草稿 map。
5. 页面级 `保存模型价格` 将变化后的 option 值发送到 `PUT /api/option/`。

## 错误处理

现有表单校验和错误展示保持不变。

唯一新增关注点是窄屏布局溢出。Header 必须通过换行、截断和弹性间距处理长模型名，
确保模型名不会和操作按钮重叠。

## 测试

手动检查：

- 桌面端价格设置页：
  - 打开已有模型；
  - 确认无需滚动即可看到 `取消` 和 `更新`；
  - 分别更新三种价格模式：按 token、按请求、表达式；
  - 确认点击 `更新` 后表格草稿内容发生变化。
- 新增模型流程：
  - 确认主按钮文案为 `添加`；
  - 确认提交后草稿中新增对应模型配置。
- 移动端 / 窄屏：
  - 打开 Sheet；
  - 确认 Header 操作按钮能正常换行，不与模型名重叠；
  - 确认提交和取消仍可用。
- 确认最终入库仍需要点击页面级 `保存模型价格`。

自动化检查：

- 实现后运行前端类型检查、构建或本项目对应的前端验证命令。
