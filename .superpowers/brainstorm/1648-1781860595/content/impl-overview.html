方案 A — 实现要点总览（剩余章节）

迁移路径已选「一次性」。下面是其余 4 块的实现方案，请过一遍，有要调整的告诉我。

1. 渠道选择 / 缓存适配
InitChannelCache 改为：channel_groups JOIN channels，按 group_id × models 构建 group2model2channels
GetRandomSatisfiedChannel / GetChannel 入参 group 名 → group_id (int)
调用链：middleware 解析 token.group_id（=0 则取 user.group_id）→ 选渠道
abilities.GetChannel(group_id, model) 同步改；缓存 key group name → group_id
2. 倍率迁移（GroupRatio map → groups 字段）
groups.group_ratio / topup_ratio 成为权威源
迁移时把 GroupRatio map 每个 entry 写入对应 groups 行
运行时 GetGroupRatio 从 groups 表读（带缓存），替代内存 map
GroupRatio map 保留为「导入/导出/批量编辑」配置格式
3. API / 前端改造
新增分组管理 CRUD：GET/POST/PUT/DELETE /api/group（改名/停用/排序/倍率）
users & channels 接口 group 字符串 → group_id；前端改下拉选择（数据源 /api/group）
前端新增「分组管理」页（web/default/src/features/system-settings/...）
4. 行为 / 错误处理 / 测试
  • 改名：UPDATE groups.name，校验唯一；default 保留分组可改名但不可删
  • 删除：软删除(deleted_at + status=disabled)，有引用也允许（等价停用）
  • 降级链：token.group_id 指向已停用分组 → 回退 user.group_id → 再回退 default
  • 迁移回滚：迁移前要求 DB 备份；事务失败 → 恢复备份；提供 dry-run 预扫描唯一分组名
  • 测试（遵循 Rule 9）：迁移幂等性、改名跟随、历史不变、group_id 路由、倍率生效；testify require/assert + 确定性表驱动
一次性迁移的维护窗口要求
  • 迁移期间进入只读/维护模式（拒绝写请求或短暂停服）
  • 大表（users / abilities）回填耗时 → 迁移脚本分批处理 + 进度日志
  • 迁移完成 → 立即切读 group_id + 删除旧列 → 恢复服务
⚠️ 三个我替你默认了的开放点，请确认
  • API 入参兼容：对外 API 仍接受 group name，后端自动解析为 id（降低前端/下游改动）—— 还是硬切只收 group_id？
  • default 分组：可改名但不可删 —— 还是完全锁死（不可改名不可删）？
  • 倍率 map：保留为导入/导出格式 —— 还是彻底废弃、只认 groups 表？

这 4 块要点 + 3 个开放点，有要调整的吗？确认后我就把完整设计落成 docs/superpowers/specs/2026-06-19-group-relation-redesign-design.md。
